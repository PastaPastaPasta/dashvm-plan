# R10-10 plan: nested-call authority, no reentry, one atomic effect and resource scope

Working artifact. Never staged, never committed. Delete when the task ships.

Task: implement explicit delegated rights, distinct signer/caller identity, no
active-contract reentry and one shared atomic effect/resource scope. Actual nested
failures poison the whole call; internal speculative retries are not failures.
Workstream 50-CALLS (#4687), section 10, modules AUTH, CALLS, VIEW, refinement FIX-12,
enables CAP-14. Release target 5.0-dev, base `v5.0-dev`, tier xhigh (confirmed: this is
the VM boundary and the rollback discipline of block execution).

## 1. Acceptance in my words

Q05 (confirmed). While an outer invocation runs, the set of contracts currently on the
call stack is tracked. Entering a contract that is already on that stack is rejected,
whether directly (A calls A) or through an intermediary (A calls B, B calls A). Plain
Rust helper calls and local recursion inside one contract frame are not calls on that
stack and are only bounded by the logical stack limits the runtime enforces. Calls
between named modules of the same contract are internal frames, not contract frames:
they never trip the reentry check and cannot be used to leave and re-enter a contract.

Q06 (confirmed). Any actual failure inside the call tree (an unauthorized right use, an
exhausted budget, a rejected native action, a host operation failure, a failed nested
call) latches the outer invocation as failed at the moment it happens. Guest code may
observe the failure value, but returning success afterwards does not un-latch it; the
outer outcome is a paid failure and every application effect of the whole tree is rolled
back. Only the integration layer owns the latch. Expected business alternatives are
ordinary typed success values and never touch the latch. An attempt that the executor
discards (a speculative retry) rolls back exactly the same way but produces no outcome at
all: no charge, no nonce effect, no receipt. Node faults (storage errors, broken build)
are a separate error channel that propagates as an internal error and is never
converted into a paid failure.

Q07 (confirmed). Every frame carries three separately readable facts: the original
transaction signer (identical in every frame of the tree), the immediate caller (the
signer at the root, the calling contract in nested frames) and the executing contract.
A callee receives exactly the rights its caller explicitly delegated, and a caller can
only delegate rights it holds itself, with bounds that can shrink but never grow. There
is no code path that derives a callee's rights from the signer identity, so the signer's
authority is never passed along automatically. A contract's own resources are governed
by its own authority in its own frames and by explicit delegation elsewhere.

Named-module scope (confirmed). A module frame shares its contract frame's signer,
caller, executing contract, rights, budget and effect scope. It is not a contract frame
for the reentry rule and cannot address any other contract.

Shared resource scope (title). One computation budget and one host-call counter serve
the whole tree: a nested call spends from its caller's remaining budget and cannot open
a fresh one, reset it or exceed it. Exhaustion anywhere is an actual failure.

### Part 1: the atomic effect scope in Drive (module VIEW)

Crate `drive`, feature `server`. New module `packages/rs-drive/src/execution/`:

- `mod.rs`: module doc (ordered execution state for invocations; the sequential backend
  wraps the real GroveDB transaction; only ABCI commits) and re-exports.
- `scope.rs`: `InvocationScope<'db, 'a>`.

```rust
#[must_use = "close the scope with keep() or roll_back(); dropping it rolls back"]
pub struct InvocationScope<'db, 'a> {
    drive: &'a Drive,
    transaction: &'a Transaction<'db>,
    closed: bool,
}

impl<'db, 'a> InvocationScope<'db, 'a> {
    /// Sets a savepoint on the transaction. Must be opened before the invocation writes
    /// anything to the transaction (see the residue rule below).
    pub fn open(drive: &'a Drive, transaction: &'a Transaction<'db>) -> Self;
    /// `Some(transaction)` for every Drive call made inside the scope.
    pub fn transaction(&self) -> TransactionArg<'db, 'a>;
    /// Accepts every write made since `open`. The savepoint stays on the transaction
    /// stack (no pop primitive exists); the residue is inert because nothing was written
    /// between the caller's own savepoint, if any, and this one.
    pub fn keep(self);
    /// Undoes every write since `open` and evicts the Drive block caches that could hold
    /// values derived from those writes (today: the contract block cache).
    pub fn roll_back(self) -> Result<(), Error>;
}

impl Drop for InvocationScope<'_, '_> {
    /// An unclosed scope (a `?` propagating a node fault) rolls back so the transaction
    /// stack is left exactly as the caller saw it; a rollback failure is logged, the
    /// node fault that caused the early exit is already propagating.
    fn drop(&mut self);
}
```

Rules the scope documents and tests:

- One scope per outer invocation. Nested calls and module calls share it; the API offers
  no nesting. The session in Part 2 is the only intended owner.
- Open-before-write. The scope's savepoint must be the first thing an invocation does to
  the transaction, so that a later `rollback_to_savepoint()` by the proposer loop (which
  pops the most recent savepoint) lands on a state identical to the loop's own savepoint.
  This is the same residue argument the loop already relies on; a test pins it.
- Rollback covers state and cache. Only the contract block cache can hold values derived
  from in-scope writes today (fetches inside a transaction insert into it; `update_contract`
  inserts into it). Global cache inserts only happen without a transaction, so they are
  unreachable from a scope. Eviction of the whole block cache is used rather than a
  per-key journal: eviction is always safe, repeatable and fee-neutral (cache hits replay
  the stored fetch cost through `CalculatedCostOperation`), and it keeps the rule simple
  until a guest-reachable cache appears that cannot be evicted wholesale.
- Not versioned. Nothing on a block path calls it in this part; the versioned Drive
  method that first uses it (R10-04) carries the version slot, exactly as
  `BlockComputationBudget` carries none. The `DriveOperationsMethodVersion.rollback_transaction`
  slot is for whole-transaction rollback and is untouched.
- `roll_back` failure is `Error::GroveDB(StorageError)` propagated as a node fault; the
  caller's `Err` path leads to an internal error result and, on a proposer, the loop's own
  rollback (which now hits the loop's savepoint because Drop popped ours).

Types and rules:

- `Principal`: `Identity(Identifier)` or `Contract(Identifier)`. Contracts are their own
  native owners, never keyless identities.
- Rights vocabulary (provisional; the capability catalogue and INT-ACL extend it):
  `ResourceSubject::{Credits { owner }, Tokens { owner, token_id }, Documents { owner, contract_id, document_type }}`,
  `RightAction::{Spend, Mutate}`, `Right { subject, action, limit: Option<u64> }`.
  `RightsSet` is a `BTreeMap<(ResourceSubject, RightAction), Option<u64>>` with a
  constructor that rejects more than `limits.max_delegated_rights_per_call` entries.
- Delegation is attenuation only: `requested` is accepted when every entry has the same
  subject and action in `held` and its limit is `Some(n)` with `n <= held limit` (an
  unbounded held right may be delegated bounded or unbounded; a bounded held right may
  not be delegated unbounded). Anything else is `Failure::UndelegatableRight`.
- Root frame: signer `s`, caller `Principal::Identity(s)`, executing contract `c`, rights
  = the rights the signer declared on the invoke (passed in by the executor). Nothing is
  derived from the signer's identity.
- Nested contract frame: signer unchanged, caller `Principal::Contract(current executing)`,
  executing = callee, rights = the attenuated set the caller passed. The callee's own
  contract authority is implicit in its frame: `authorize(right)` passes when
  `right.subject.owner == Principal::Contract(executing)` or the frame's rights cover it,
  otherwise `Failure::Unauthorized` latches. Native validation of the action itself
  (Drive/DPP) still applies after this gate; this is the delegation gate only.
- Module frame: `Frame::Module { contract_id: executing, module: ModuleIndex(u16) }`.
  Context lookups resolve to the nearest contract frame, so signer, caller, rights and
  authority are identical. Not counted against `max_active_contract_frames`; not subject
  to the reentry check; cannot name another contract (the API takes no contract id).
- `ActiveContractStack`: `push(callee)` fails with `Failure::Reentry { contract_id }` when
  the id is anywhere on the stack (root included) and with
  `Failure::ContractDepthExceeded { limit }` when the depth would exceed
  `max_active_contract_frames` (root counts as one, matching the register's "8 including
  the root").
- `InvocationBudget`: checked counters for computation units (`u64`) and host calls
  (`u32`) created from the reserved bound; `charge_computation(units)` and
  `count_host_call()` latch `Failure::ComputationExhausted` / `Failure::HostCallsExhausted`.
  There is one budget per session; frames hold no budget of their own.
- `InvocationSession<'db, 'a>` owns `InvocationScope` (Part 1), the stack, the budget and
  the latch `poison: Option<Failure>` (first failure wins).

```rust
pub type CallResult<T> = Result<T, Failure>;          // deterministic outcome of guest or host work
pub type HostResult<T> = Result<CallResult<T>, Error>; // outer Err is a node fault, never latched

impl InvocationSession {
    pub fn open(drive, transaction, root: RootInvocation, limits: CallTreeLimits, budget: InvocationBudget) -> Self;
    pub fn context(&self) -> CallerContext<'_>;
    pub fn transaction(&self) -> TransactionArg<'db, '_>;
    pub fn call_contract<T>(&mut self, callee: Identifier, rights: RightsSet,
                            body: impl FnOnce(&mut Self) -> HostResult<T>) -> HostResult<T>;
    pub fn call_module<T>(&mut self, module: ModuleIndex,
                          body: impl FnOnce(&mut Self) -> HostResult<T>) -> HostResult<T>;
    pub fn authorize(&mut self, right: &Right) -> CallResult<()>;
    pub fn charge_computation(&mut self, units: u64) -> CallResult<()>;
    pub fn count_host_call(&mut self) -> CallResult<()>;
    pub fn fail(&mut self, failure: Failure) -> Failure;   // latch (idempotent), returns it to propagate
    pub fn is_poisoned(&self) -> bool;
    pub fn finish(self) -> Result<InvocationOutcome, Error>; // keep or roll back, then the outcome
    pub fn abandon(self) -> Result<(), Error>;               // roll back, no outcome (speculative discard)
}
```

  `call_contract` pushes the frame (or latches and returns `Ok(Err(..))`), runs the body,
  pops on every exit, and latches any `Ok(Err(failure))` the body returns. The body gets
  `&mut Self`, so nested work shares the session by construction; `finish` and `abandon`
  take `self` and are unreachable from inside a body. `finish` keeps the scope on a clean
  latch and returns `Succeeded { consumed }`, otherwise rolls back and returns
  `Failed { failure, consumed }`; both carry `Consumption { computation_units, host_calls, max_contract_depth }`
  for the executor to settle against its `ComputationReservation` (R10-04 wiring).
  `abandon` rolls back and returns nothing: no outcome exists to charge.
- `Failure` variants: `Reentry`, `ContractDepthExceeded`, `Unauthorized`,
  `UndelegatableRight`, `TooManyDelegatedRights`, `ComputationExhausted`,
  `HostCallsExhausted`, `NativeActionFailed(Box<ConsensusError>)`, `Host(HostFailure)`,
  `Guest(GuestFailure)` (`Trap`, `Rejected { code }`). `Failure::family()` maps each to the
  DVM-01 symbolic family (`Unauthorized`, `ResourceExceeded`, `NativeActionFailed`,
  `GuestTrap`, `GuestRejected`). Numeric consensus error codes are not allocated here:
  no transition can reach this crate yet, and code allocation is A02/A03 work (R05-03,
  R12-07). The PR body says so.

## 5. Provisional values and interpretations (all go in the PR bodies)

1. `max_delegated_rights_per_call = 64` (Part 3): no register row; chosen to bound the
   attenuation work of one call while leaving room for realistic delegations.
2. The rights vocabulary (`Credits`, `Tokens`, `Documents` subjects; `Spend`, `Mutate`
   actions; optional amount limit) is the smallest typed shape that lets delegation be
   explicit and attenuating. The capability catalogue (CAP-*) and INT-ACL extend it.
3. Reentry and depth failures are classified under the DVM-01 `Unauthorized` and
   `ResourceExceeded` families respectively; numeric codes wait for the allocation register.
4. Module frames are not charged here (the host-mediated typed call cost belongs to
   R08-04 and the metering generation); they only carry context and the shared counters.
5. Block-cache eviction on rollback is wholesale rather than per key (safe, repeatable,
   fee-neutral); revisit when a guest-reachable cache appears that cannot be evicted wholesale.
6. The savepoint residue on `keep()` is accepted with the open-before-write rule, exactly as
   the proposer loop accepts it today. The structural fix is a pop-savepoint binding
   (`Transaction::PopSavePoint` in the rust-dashcore rocksdb fork's C shim, `Tx::pop_savepoint`
   in grovedb storage, a pin bump here); recorded as a follow-up, not blocking.
7. Scheduled invocations have no signer principal yet; `RootInvocation` takes a signer
   identity because that is the only origin that exists in the tree. R10-05 extends the
   origin when jobs land.
