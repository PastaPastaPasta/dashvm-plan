## Acceptance in my words

Public documentation in this repository (README, the mdBook under `book/`, `docs/`, the mobile SDK package READMEs) must state:

1. **Smart-contract target wording.** Smart contracts are not "planned for Platform v4.0 (targeted for mainnet in 2027)". Platform 4.0 shipped on 2026-07-01 without them. The correct statement: smart-contract execution (DashVM: Rust contracts compiled to WebAssembly, executed on Wasmtime with Cranelift, decisions R01, R34, Q03) is in development toward Platform 5.0, tracked in dashpay/platform issue #4626. No calendar dates, no mainnet year, no claim that PV15/PV16/PV17 exist, no `v4.2-dev` branch instructions.
2. **Protocol and version counts.** The tree has fourteen protocol versions (`LATEST_VERSION = PROTOCOL_VERSION_14`, `PLATFORM_VERSIONS` has 14 entries, `LATEST_PLATFORM_VERSION = &PLATFORM_V14`), 47 workspace members, workspace version `4.2.0-dev.8`, Rust 1.92. The book says twelve versions, 44 crates, `3.0.1`.
3. **State-transition lists.** `StateTransition` has 21 variants and `StateTransitionType` runs 0 to 20 (six shielded-pool transitions were added at PV12). The book shows 15 and stops at discriminant 14. The document sub-transition list misses `IndexOnlyDelete`. The "which transitions have no signature" rule lists two names; the real `signature()` returns `None` for nine.
4. **Swift and Kotlin availability.** Both SDKs exist in-tree (`packages/swift-sdk`, `packages/kotlin-sdk`), on `master` as well. README and book say "Coming in v3.1" / "Coming in v3.2" with no Android package. `docs/SDK_ARCHITECTURE.md` still calls the Kotlin SDK "Planned". The Swift README's install section names a `swift-sdk` Cargo crate that does not exist and `swift_dash_*` C symbols that do not exist.

No capability rows, no DIP allocation, no consensus behaviour. DVM-01 line 24 ("Smart execution targets 5.0-dev; earlier preparation does not enable it") and line 65 ("Release branch names 4.3-dev/4.4-dev/5.0-dev are engineering destinations, not assigned protocol numbers... this draft does not invent three required activations") are the wording rules I follow.

6. **Kotlin feature matrix.** Set from the package README's feature list, not from a fresh audit; `PARITY_SUMMARY.md` records partial support for some capabilities and is linked instead of re-graded.
