## 1. Acceptance restated

Kind `test`, tier xhigh, modules HOST, ABCI, HARNESS, section 4 of the parent plan, source row S04-06, workstream issue #4689. No extra acceptance paragraph and no capability requirements are recorded. The task ships when tests that drive the real block-execution entry points demonstrate all of the following:

1. **Classified paid outcomes.** Every deterministic guest failure of an outer contract invocation lands in the block as a `PaidConsensusError` whose consensus error carries the family the protocol draft allocates (`GuestRejected`, `GuestTrap`, `ResourceExceeded`, `NativeActionFailed`; allocation register entry A03, owned by R12-07). The signer is charged exactly once for the consumed work (native processing plus metered computation priced through `computation_units_to_credits`), the applicable native nonce is bumped under the paid-failure rule, and no application effect of the invocation survives (documents, credit buckets, tokens, nested effects are all rolled back). Four failure sources are each covered:
   - an explicit guest rejection (the guest returns the ABI's rejection result after having written state);
   - invalid host arguments (pointer outside memory, length over the argument cap, return over the return cap, unknown operation id, undecodable typed request, request for a mutation the declared capabilities do not grant);
   - a WebAssembly trap (`unreachable`, integer division by zero, out-of-bounds load, indirect call to a null table slot);
   - exhaustion of a deterministic bound (computation units, logical stack, memory pages, host-call count, nesting depth).
2. **Node faults stay distinct.** A genuine storage or node fault during guest execution (a Drive `Err` inside a host operation, a missing compiled artifact, an unexpected engine trap) is never a paid outcome. It surfaces as an `InternalError` result or a block-level `Err`, exactly like today's node-local failures: the proposer strips the transition, a validator rejects the block, nothing is charged, no nonce moves, nothing commits. The healthy twin commits the block; the repaired node re-executes it to the same app hash.
3. **Recovery behaviour preserved.** The `StateTransitionExecutionResult` to `TxAction` mapping in `prepare_proposal`, the `unexpected_execution_results` gate in `process_proposal`, the proposer-side savepoint rollback of stripped transitions and the node-level exception path are unchanged and still hold with contract work in the block, including a mixed block (native success, guest paid failure, injected node fault).
4. **Per-block exhaustion is admission, not failure.** An invocation whose admitted bound does not fit the block's remaining computation is delayed by the proposer and rejected by a validator, never charged part-way (the `BlockComputationBudget` contract merged by R06-01).

## 3. Why the task is blocked

The four things the title asks to test are guest execution outcomes. On this base there is no guest execution: no runtime that can trap or run out of computation (R08-01 parts 2 and 3), no host adapter that decodes and validates guest-supplied arguments (`rs-drive-contracts`, first delivered by the HOST tasks; R10-01 owns the call transition, its ABI, structured errors and bounded host operations), no settlement that turns a guest fault into a `PaidConsensusError` with a charge and a nonce rule (R12-07, which also allocates the error families against the registry), and no explicit fault classification or injection seam on the proposer and validator paths (R11-03).

FIX-03 already represented the paid-guest class by its native analogue (a paid consensus error on a contract update) and said so in its PR body. Repeating that as R04-04 part 1 would transform the task into a re-pin of existing behaviour and duplicate FIX-03; the one genuine gap (section 2) belongs to the node-fault case and is covered here once the node-fault seam exists. The task therefore waits, and this plan is the design the resuming lane refines.

Discovered prerequisites (direct): R08-01 (runtime outcome and trap classification, `dashvm`), R10-01 (call transition, ABI rejection result, capability declarations, bounded host operations), R12-07 (paid outcome settlement, nonce and cost handling, error codes), R11-03 (fault classification and injection on proposer, validator and scheduled paths). R08-05 (execution seam, live affordability, metering integration) and R06-02 (block ledger enforcement) arrive transitively through R12-07. R08-07 (author SDK, native harness) is deliberately not a prerequisite: fixtures are hand-written WebAssembly text (section 4.1). R10-03 (receipts) is not a prerequisite: receipt assertions are conditional (section 8).

## 4. Test design

### 4.1 Fixture guest module (`outcomes.wat`)

One canonical module, hand-written WebAssembly text, importing only the `dash_host` envelope (`host_call`, `response_len`, `response_read`, `response_release`; names from `dashvm_validation::abi_names`, possibly renamed by R08-04) and exporting `memory`, `dash_alloc` and these entries (each `(args_ptr: i32, args_len: i32) -> i64`):

| Entry | Behaviour | Expected family (provisional) |
|---|---|---|
| `ok` | writes one marker document, returns success | success (control) |
| `reject` | writes the marker, returns the ABI rejection result | `GuestRejected` |
| `trap_unreachable` | writes the marker, `unreachable` | `GuestTrap` |
| `trap_div_zero` | `i32.div_s` by zero | `GuestTrap` |
| `trap_oob` | `i32.load` at `0xFFFF_FFF0` | `GuestTrap` |
| `trap_indirect` | `call_indirect` to a null slot | `GuestTrap` |
| `exhaust_compute` | writes the marker, then `loop br 0` | `ResourceExceeded` (computation) |
| `exhaust_stack` | unbounded self recursion | `ResourceExceeded` (logical stack) |
| `exhaust_memory` | `memory.grow 1` until the guest sees `-1`, then a load past the last page | `ResourceExceeded` or `GuestTrap` per the runtime's page-cap rule; the vector pins which |
| `exhaust_host_calls` | cheap host op in a loop past the per-invocation cap | `ResourceExceeded` (host calls) |
| `bad_ptr` | `host_call` with `in_ptr` beyond memory | `GuestTrap` (envelope violation) |
| `bad_len` | `host_call` with `in_len` above the argument cap | `GuestTrap` (envelope violation) |
| `ret_too_large` | returns a packed `(ptr, len)` with `len` above the return cap | `GuestTrap` (envelope violation) |
| `bad_op` | `host_call` with an unallocated op id | `NativeActionFailed` |
| `bad_request` | known op, undecodable request bytes | `NativeActionFailed` |
| `unauthorized_write` | a write the contract's declared capabilities do not grant | `NativeActionFailed` |
| `caught_then_ok` | performs `bad_request`, ignores the fault code, returns success | still a paid failure: the poison latch is owned by the host (DVM-06) |

Nesting exhaustion (`NestingLimit`) is added only if R10-10 (nested calls) has merged; otherwise it is listed as deferred in the PR body. The module is stored as text under `packages/rs-drive-abci/tests/supporting_files/dashvm/outcomes.wat` and assembled at test time with the `wat` crate pinned to the line the validator crate uses (`=1.236.0`), so reviewers read source. Registration goes through the real contract create transition (R06-05's large envelope, R10-01's declarations), so preparation and readiness are the node's own.

### 4.2 Paid outcome matrix (unit level, both paths)

Location: `#[cfg(test)]` tests next to the settlement code R12-07 lands (the ABCI catalog names `execution/contracts/settlement.rs`; adjust to the merged layout). Each test builds a platform with `TestPlatformBuilder`, seeds a funded identity, registers the fixture contract, then calls `process_raw_state_transitions` with one direct call per entry, once with `proposing_state_transitions = true` and once `false` (same shape as the shield and top-up injection tests). Assertions per entry:

- the result is `PaidConsensusError { error, actual_fees, .. }` and `error`'s family equals the table above (through the accessor R12-07 provides; never a numeric literal except in the strategy `expect_specific_block_errors_with_codes` lists, which read the code from the error);
- `actual_fees.processing_fee` equals the vector's value and is at least `computation_units_to_credits(consumed, platform_version)`; `storage_fee` is zero unless a failure receipt was reserved (section 8); the signer's balance dropped by exactly `total_base_fee`; a second identical call in a fresh transaction charges the same amount (determinism);
- the signer's nonce in the applicable domain advanced by one;
- the marker document is absent, the contract's credit bucket and the signer's other balances are unchanged, and the root hash equals that of a control run that executed only the nonce bump and the fee (built by a control entry that fails before any write, `trap_div_zero`, with the same charge; where charges differ the test compares state reads instead of roots);
- `try_into_platform_versioned` yields an `ExecTxResult` with `code == error.code()` and `gas_used == total_base_fee`.

The block ledger case: two calls each reserving more than half the per-block limit in one block; the first settles, the second is `NotExecuted` on the proposer (delayed, not charged, nonce untouched) and a validator given a block carrying both rejects it. Read `BlockComputationBudget` semantics from R06-02's merged enforcement.

### 4.3 Node-fault matrix (strategy level, twins)

Location: `packages/rs-drive-abci/tests/strategy_tests/test_cases/guest_outcome_tests.rs`, twin platforms from one seed (FIX-03 pattern), healthy prefix of five blocks with identity inserts and the fixture contract registered at block 2. Injection through `testing-config` hooks in the host adapter (requested from R11-03; if absent when this lane resumes, add `PlatformTestConfig::guest_host_fault: Option<GuestHostFault>` with variants `StorageErrorOnHostCall(u32)`, `ArtifactMissing`, `UnexpectedTrap`, defaulting to `None`, following FIX-03's shape).

1. **Proposer side.** Twin A armed, twin B healthy. Both prepare the same block (one identity create, one `ok` call). A reports the call as `InternalError`, `TxAction::Removed`, its writes rolled back to the savepoint (marker absent, signer balance and nonce untouched), and A's app hash equals B's app hash for the block that never contained the call. B processes A's prepared block and accepts with the same hash and results.
2. **Validator side (closes the gap in section 2).** B, healthy, prepares a block containing the call; A, armed, processes it: `ProposalStatus::Reject`, committed root, height and nonce unchanged, nothing charged. A is disarmed, processes the identical request, accepts with B's app hash and `tx_results`; both finalize; committed roots equal.
3. **Artifact loss.** A's compiled artifact for the fixture is removed (runtime cache API from R08-01 part 2); the call fails as a node fault on A only; after the artifact is rebuilt from canonical bytes A reproduces B's block. Skipped with a note if the cache exposes no removal API to tests.
4. **Never a paid record.** In all three, no `PaidConsensusError` appears for the faulted call on the faulted node, no receipt exists (if receipts exist), and the fee pools moved only by the transitions that stayed.

### 4.4 Recovery preservation

- **Mixed block.** One native success (identity create), one guest paid failure (`trap_unreachable`), one injected node fault (`ok` call with `StorageErrorOnHostCall`), one native paid failure (identity update with a wrong revision, code 40203). Proposer keeps the success and both paid failures, strips the node fault; a validator accepts the three-transaction block; twins agree on app hash and `tx_results`; the chain continues five blocks with equal roots.
- **Malicious proposer.** A validator given a block that includes the node-faulted call (built by a twin with the hook off, where the call succeeds) executes it successfully, because on the validator the call is not faulted; a validator given a block that includes a call its own node cannot execute (hook on) rejects. Both are the existing rules, restated for guest work.
- **Class 3 untouched.** The FIX-03 module runs unchanged in the same gate; no scheduled-path guest tests here (R11-12).

### 4.5 Shared vectors

`outcome_vectors.json`: for each fixture entry, `(entry, args) -> (family, computation_consumed, processing_credits, storage_credits, nonce_delta, effects_retained: false)`, generated from the metered runtime under `PlatformVersion::latest()` and asserted by both the unit tests and, if `packages/rs-dash-contract-test` exists, by a harness `runner` test under its native integration feature that executes the same entries without ABCI. The vector file lives in the harness crate when it exists, otherwise under `packages/rs-drive-abci/tests/supporting_files/dashvm/` with a move noted for R08-07. Native reference helpers never supply the numbers (DVM-07).

## 8. Provisional values and interpretations (every one goes in the PR body)

1. Family mapping per fixture entry (table in 4.1) pending allocation A03 by R12-07; tests assert families through the accessor, so a re-allocation changes the table, not the tests.
2. Invalid host arguments split into envelope-level violations (pointer, length, return cap: guest faults, `GuestTrap`) and typed-level refusals (unknown op, undecodable request, ungranted mutation: `NativeActionFailed`); both paid, both roll back.
3. A caught host fault cannot restore success (`caught_then_ok`): the host owns the poison latch (DVM-06).
4. Node faults are `Err` from the executor mapped to the existing `InternalError` result; `ArtifactMissing`, `UnexpectedTrap` and a storage `Err` inside a host call are node faults per R08-01's outcome design and are never charged.
5. Per-block computation exhaustion is admission (delayed by the proposer, rejected by a validator), following R06-01's ledger documentation.
6. Vectors pin determinism under the active provisional prices and are regenerated when R12-03 or R12-04 change them; they are not price evidence.
7. Hand-written WebAssembly text fixtures instead of Rust-built guests, so the task does not wait for the author SDK (R08-07).
8. Receipt assertions (one failure receipt per paid failure, none for node faults or delayed calls) apply only if R10-03 has merged; otherwise omitted and named as deferred.
9. Scheduled-path traps and exhaustion stay with R11-12; nesting-limit exhaustion waits for R10-10.
10. Harness placement of the vectors depends on whether `rs-dash-contract-test` exists at implementation time.
11. The strategy module joins the PR gate only under the ten-second threshold.
