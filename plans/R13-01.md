# PLAN R13-01: guest-compatible value/ABI foundation and canonical codec

Working artifact. Never staged, never committed. Delete when the task ships.

Base: `v4.3-dev` at `d02072827f` (worktree branch `dashvm/r13-01`). Latest protocol
version in tree: 14. Toolchain 1.92 with `wasm32-unknown-unknown` installed.

## 1. Acceptance in my words

1. `platform-value` and `platform-serialization` gain a real allocation-only
   profile (`no_std + alloc`) selectable through Cargo features. The guest
   profile excludes the native `PlatformVersion` registry, OS entropy, JSON/CBOR
   conveniences, thread-local state and every std-only helper. The native
   default profile keeps every existing type, encoding and behaviour
   byte-for-byte and behaviour-for-behaviour.
2. Guest decoding no longer relies on the thread-local depth limit. An explicit
   bounded decoding context (bytes, depth, element count) is passed by the
   caller. The native path keeps its historical thread-local behaviour because
   shipped protocol versions decode through it.
3. A new small crate `dashvm-abi` (directory `packages/rs-dashvm-abi`) provides
   the minimal ABI foundation: the ABI generation marker, explicit codec bounds,
   a canonical bounded value codec over the shared value encoding, structured
   bounded codec errors, and golden vectors shared between native and guest
   builds. It depends only on the alloc-only value/serialization profile,
   `bincode` and `thiserror`. No DPP, Drive, platform-version, client, Wasmtime,
   entropy or database dependency.
4. Separate guest-target builds are verified: `wasm32v1-none` (a target with no
   std library at all, so any std leak is a compile error) and
   `wasm32-unknown-unknown` (the deployment target), from a separate guest
   workspace with its own lockfile, plus dependency-tree bans in CI.
5. Dependency direction is preserved: `dash-platform-queries ->
   drive-proof-verifier -> drive (verify)` is untouched; `platform-version`
   never imports `dashvm-abi`; `dashvm-abi -> platform-value ->
   platform-serialization` only.
6. Exact package names are settled (section 4).

Out of scope, by the workstream completion criteria: host-call ABI, request/
result envelopes, handles, manifests/bundle descriptors, capability IDs, method
IDs, context representations (R08-04, R08-03, CAP-02, SDK-01, all 5.0 or
44-AUTHOR). No protocol-version table changes, no fees, no consensus errors.

## 2. Tree facts that shape the design (drift check against the issue)

- The issue inspected `5f1e0ccd`; this tree is `d02072827f`. The anchors still
  hold: `packages/rs-platform-value/src/lib.rs:54` is the thread-local depth
  limit, `packages/rs-platform-serialization/src/lib.rs:28-29` are the
  unconditional `extern crate alloc; extern crate std;`,
  `packages/rs-platform-value/Cargo.toml` depends on `platform-version` and
  `platform-serialization` unconditionally. Nothing in the two crates changed
  since the issue was written except test coverage commits.
- The only use of `platform-serialization`/`platform-version` inside
  `platform-value` is `types/identifier.rs:48-66` (`PlatformVersionEncode` and
  `PlatformVersionedDecode` for `Identifier`).
- `rand` is used by `types/identifier.rs` (`Distribution`, `random`,
  `random_with_rng`) and `types/bytes_32.rs` (`random_with_rng`). 108 files in
  the workspace call `Identifier::random`/`random_with_rng`, all native.
- `treediff` is used only by `patch/diff.rs` and is std-only upstream.
  `patch::patch` and `patch::merge` are alloc-clean. Only
  `rs-dpp/src/tests/fixtures/get_dashpay_document_fixture.rs` imports
  `platform_value::patch` (`merge`), plus the crate's own `tests/coverage_tests.rs`
  (`diff`, `merge`).
- `indexmap` appears in two functions returning `IndexMap<String, &Value>` with
  the default `RandomState` hasher (std-only): `value_map.rs`
  `map_ref_into_indexed_string_map` and `inner_value.rs`
  `inner_optional_index_map`. Consumers: `rs-dpp` `try_from_schema` (two call
  sites), native.
- `HashSet<&str>` parameters exist on two `replace.rs` methods
  (`replace_to_binary_types_of_root_value_when_setting_at_path`,
  `replace_to_binary_types_when_setting_with_path`). No consumer outside the
  crate.
- `Value` derives bincode `Encode`; `Decode<Context>` is a hand-written
  iterative state machine that is generic over every bincode context (dpp
  derives `Decode` on types with `Value` fields using a generic `__Context`, so
  the blanket impl must stay). Variant indices 0..=22 are wire-significant and
  never change.
- `rs-dpp/src/state_transition/mod.rs:805` is the single consumer of
  `with_value_decode_depth_limit` (from `SystemLimits.max_document_value_depth`,
  `Some(256)` since `SYSTEM_LIMITS_V3`).
- `Value` decode does `Vec::with_capacity(len)` after
  `claim_container_read`, which is a no-op when the bincode config has no
  limit. The native transition path always decodes with a byte limit
  (`platform_serialize(limit = 100000)` on `StateTransition`), so the
  allocation is bounded there. The guest path must not rely on that.
- CI (`.github/workflows/tests-rs-workspace.yml`) already has a "Check
  transport-free feature cuts" step with `cargo tree` bans; the guest cut will
  follow the same shape. `cargo clippy --workspace --all-targets --all-features
  -- -D warnings` and `cargo machete` run on every PR. `platform-value` and
  `platform-serialization` are in the nextest package list.
- Empirical checks I ran in a scratch crate on this toolchain: `bincode 2.0.1`
  (`alloc`, `derive`, `serde`), `serde` (`alloc`, `derive`, incl.
  `serde::de::value::SeqDeserializer`), `thiserror 2` (no `std`), `bs58`,
  `base64`, `hex` (`alloc`), `indexmap`, `ciborium` (no default features) all
  build for `wasm32v1-none`. `[T]::join`, `serde::ser::Error`/`de::Error` impls
  on a thiserror enum, and a `$crate::__private::vec!` re-export inside a
  `#[macro_export(local_inner_macros)]` macro all work from a downstream
  `#![no_std]` crate. Listing `wasm32v1-none` in `rust-toolchain.toml` makes
  rustup install it on first use (observed locally). `cargo check -p <member>
  --target wasm32v1-none` inside a workspace resolves only that member's
  feature graph (a std-using sibling did not unify `bincode/std` into it).

## 3. Approach

Two sequential parts. Part 1 refactors the two existing crates; part 2 adds the
new crate, vectors, guest workspace and CI bans. Part 1 compiles and passes CI
alone; part 2 depends on part 1.

`src/bounded.rs` (new, alloc profile, owned by SER per the module catalog)

```rust
/// Explicit limits for one bounded decode or encode. Supplied by the caller;
/// never read from ambient state.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct CodecBounds { pub max_bytes: u32, pub max_depth: u16, pub max_elements: u32 }

/// Running counters against one `CodecBounds`.
pub struct CodecBudget<'a> { bounds: &'a CodecBounds, depth: u16, elements: u32 }
impl<'a> CodecBudget<'a> {
    pub fn new(bounds: &'a CodecBounds) -> Self;
    pub fn check_input_len(&self, len: usize) -> Result<(), BoundsError>;
    pub fn enter_container(&mut self) -> Result<(), BoundsError>;   // depth + 1 > max_depth => DepthExceeded
    pub fn exit_container(&mut self);
    pub fn claim_elements(&mut self, count: usize) -> Result<(), BoundsError>; // checked add; > max_elements => ElementsExceeded
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum BoundsError {
    InputTooLarge { len: usize, max: u32 },
    DepthExceeded { depth: u16, max: u16 },
    ElementsExceeded { elements: u32, max: u32 },
}

/// A bincode reader over a slice that exposes the unread remainder, so callers
/// can reject declared lengths that cannot fit and detect trailing bytes.
pub struct BoundedSliceReader<'a> { remaining: &'a [u8] }
impl Reader for BoundedSliceReader<'_>;  impl<'de> BorrowReader<'de> for BoundedSliceReader<'de>;
impl BoundedSliceReader<'_> { pub fn remaining(&self) -> usize; }

/// The one bincode configuration used for canonical wire bytes: standard,
/// big endian, varint integers. Same as the native platform config.
pub const fn canonical_config() -> Configuration<BigEndian, Varint, NoLimit>;

#[derive(Debug)]
pub enum BoundedDecodeError { Bounds(BoundsError), Decode(DecodeError), TrailingBytes { remaining: usize }, DeclaredLengthExceedsInput { declared: usize, remaining: usize } }

pub fn bounded_decode_from_slice<T, F>(bytes: &[u8], bounds: &CodecBounds, decode: F) -> Result<T, BoundedDecodeError>
where F: FnOnce(&mut DecoderImpl<BoundedSliceReader<'_>, Configuration<BigEndian, Varint, NoLimit>, ()>, &mut CodecBudget<'_>) -> Result<T, BoundedDecodeError>;
// checks len <= max_bytes, runs `decode`, then requires remaining() == 0.
```

`src/guest_bounds.rs` (new, VALUE-owned per the catalog)

```rust
impl Value {
    /// Decode one value from exactly `bytes` under explicit bounds. Every
    /// container declaration is charged against the element budget before any
    /// allocation; a declared length larger than the unread input is rejected
    /// before allocating; no capacity is pre-reserved from untrusted lengths.
    pub fn decode_bounded(bytes: &[u8], bounds: &CodecBounds) -> Result<Value, BoundedDecodeError>;
    /// Encode with the canonical config. Rejects output above `max_bytes`
    /// (size pass first, no oversized allocation), depth above `max_depth` and
    /// node count above `max_elements` (iterative traversal, no recursion).
    pub fn encode_bounded(&self, bounds: &CodecBounds) -> Result<Vec<u8>, BoundedEncodeError>;
}
pub enum BoundedEncodeError { Bounds(BoundsError), Encode(EncodeError) }
```

`decode_bounded` runs the same state machine with `budget: Some(..)`: on each
Array/Map header it calls `enter_container`, `claim_elements(len)` (map: `len * 2`
checked) and the declared-length-versus-remaining check, then builds with
`Vec::new()` and pushes. Depth is the frame stack length as today.

```rust
/// Identifies one ABI wire generation. Protocol-version tables select the
/// applicable generation on the native side; this crate never chooses
/// activation policy. Numeric values are provisional until allocated in the
/// shared register.
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct AbiGeneration(u16);
impl AbiGeneration { pub const INITIAL: Self = Self(0); pub const fn new(raw: u16) -> Self; pub const fn as_u16(self) -> u16; pub const fn is_supported(self) -> bool /* == INITIAL */ }
```

`src/codec/bounds.rs`: `pub use platform_serialization::bounded::{CodecBounds, BoundsError};`
plus provisional constants with doc comments naming the register rows:

```rust
/// Provisional: 256 KiB arguments per the allocation register starting values.
pub const PROVISIONAL_ARGUMENT_BOUNDS: CodecBounds = CodecBounds { max_bytes: 256 * 1024, max_depth: 256, max_elements: 65_536 };
```

`max_depth: 256` matches the native `max_document_value_depth`. `65_536`
elements is my provisional choice (no register row exists); the constants are
test/tooling defaults, callers always pass bounds explicitly.

`src/codec/canonical.rs`: `pub fn check_canonical(value: &Value) ->
Result<(), NonCanonicalReason>`, iterative traversal (explicit stack, no
recursion): map keys must be `Value::Text`, strictly increasing in bytewise
`str` order, no duplicates; `Value::Float` must not be NaN. Bytewise `str`
order is chosen because `Value::from(BTreeMap<String, Value>)` already yields
it, so native document property maps are canonical without re-sorting.

`src/codec/encode.rs`

```rust
pub fn encode_value(generation: AbiGeneration, value: &Value, bounds: &CodecBounds) -> Result<Vec<u8>, CodecError>
// generation supported? -> check_canonical -> value.encode_bounded(bounds)
```

`src/codec/decode.rs`

```rust
pub fn decode_value(generation: AbiGeneration, bytes: &[u8], bounds: &CodecBounds) -> Result<Value, CodecError>
// generation supported? -> Value::decode_bounded (bytes, depth, elements, trailing, declared lengths)
// -> check_canonical(&value) -> re-encode with encode_bounded and compare to `bytes`;
//    mismatch => CodecError::NonCanonical(NonMinimalEncoding)
```

The re-encode comparison is the complete test for byte canonicality (bincode
decodes non-minimal varints leniently, so a decode-only check cannot see them).
Cost is one extra linear pass over at most `max_bytes`; the host charges it as
codec work when host-call pricing lands (R09-02/R12-03).

`src/errors.rs` (bounded, no strings, no OS detail; both enums tagged
`// @append_only` because they will become wire-visible later):

```rust
pub enum CodecError {
    UnsupportedGeneration { requested: AbiGeneration, supported: AbiGeneration },
    InputTooLarge { len: usize, max: u32 },
    DepthExceeded { depth: u16, max: u16 },
    ElementsExceeded { elements: u32, max: u32 },
    DeclaredLengthExceedsInput { declared: usize, remaining: usize },
    TrailingBytes { remaining: usize },
    Malformed(MalformedKind),          // UnexpectedEnd, UnknownVariant(u32), InvalidUtf8, InvalidInteger, InvalidBool, InvalidChar, Other
    NonCanonical(NonCanonicalReason),  // NonTextMapKey, UnsortedMapKeys, DuplicateMapKey, NanFloat, NonMinimalEncoding
}
```

`bincode::error::DecodeError` is mapped variant-by-variant into `MalformedKind`.

`tests/golden_vectors.rs` + `tests/vectors/`

- `tests/vectors/manifest.json`: list of `{ "name", "file", "expect":
  "ok" | "<CodecError variant name>", "description" }`.
- One `.hex` file per vector. Positive vectors cover every `Value` variant and
  the varint boundaries: `U8`/`I8` extremes, `U16` 250/251/255/256/65535,
  `U32` 65536 and `u32::MAX`, `U64` `2^32` and `u64::MAX`, `I64::MIN`, `U128`/
  `I128` extremes, `Bytes` empty and 32 bytes, `Bytes20/32/36`, `EnumU8`,
  `EnumString`, `Identifier`, `Float` (0.0, -0.0, 1.5, `f64::MAX`, one
  subnormal), `Text` (empty, ascii, multi-byte UTF-8), `Bool`, `Null`, `Array`
  (empty, mixed, nested three deep), `Map` (empty, two sorted keys, nested).
- Negative vectors: unknown variant 23, truncated payload, one trailing byte,
  non-minimal varint (`U16_BYTE` form of 5), 257 nested arrays (against
  `max_depth: 256`), declared array length beyond input, unsorted keys,
  duplicate key, non-text key, NaN float, invalid UTF-8 text. Element and byte
  bound failures are tested with small explicit bounds in code rather than large
  files.
- Assertions per positive vector: `encode_value` equals the file bytes;
  `decode_value` returns the expected `Value`; the same bytes decode identically
  through the native path (`bincode::decode_from_slice::<Value>` with the
  standard big-endian config) and the native derive `Encode` output equals the
  file bytes. This is the shared-encoding proof: guest bytes are native bytes.
- The vector table in Rust builds each expected `Value` with constructors;

## 4. Settled names and provisional decisions (all go in the PR bodies)

Settled by this task (the issue asked to settle exact package names):

- `packages/rs-dashvm-abi`, Cargo `dashvm-abi`, import `dashvm_abi`. Matches
  the proposed layout; the R08-01 lane (runtime, 5.0) confirmed it will not
  create this crate and keeps bundle descriptor types in `dashvm-validation`
  until the ABI crate owns them (R08-03/R08-04).
- The guest value/codec foundation is the existing `platform-value` and
  `platform-serialization` crates built with `default-features = false`. No new
  `platform-value-core` crate: the dependency register's phrase
  "uses platform-value-core" is satisfied by this profile.
- Feature names: `platform-value` `std`, `random`, `platform-version`, `json`,
  `cbor`; `platform-serialization` `std`, `platform-version`; `dashvm-abi`
  `std`. `json` and `cbor` imply `std` (serde_json `preserve_order` requires
  std; CBOR conveniences are native tooling).
- Guest check workspace: `packages/rs-dashvm-abi/guest-check`, package
  `dashvm-abi-guest-check`, `publish = false`, excluded from the root workspace.

Provisional (engineering choices the register leaves open; marked in code
comments and PR bodies, owned by A07/R08-04 for final allocation):

- `AbiGeneration::INITIAL = 0`; no envelope framing or hash domain is added
  (A02/A07 own those).
- Canonical map rule: text keys, bytewise `str` order, no duplicates.
- Canonical float rule: NaN rejected; other bit patterns pass through raw.
- Byte canonicality by re-encode equality.
- `max_elements` default 65,536; `max_depth` 256 (native value depth);
  `max_bytes` 256 KiB arguments and 64 KiB results (register rows).
- Element accounting: each declared array entry costs one, each map entry two
  (key and value), charged at the container header before allocation.
- No-std blanket `Decode<Context> for Value` uses the constant 256 depth limit;
  guests must use `decode_bounded` for explicit bounds.

## 5. Versioning consequences

None. No `vN` modules, no `SystemLimits`, no fee schedules, no protocol-version
tables, no consensus error codes, no proto, no SDK surfaces. Nothing here is
reachable from block execution in a new way: the native `Value::decode` path
keeps its thread-local behaviour and the state-transition decoder still calls
`with_value_decode_depth_limit` with the table value. PR titles use `feat`
without `!`.

## 6. What stays byte-identical and behaviour-identical

- `Value` variant indices 0..=22 and the derived `Encode` output.
- Native `Decode<Context> for Value` under default features (thread-local
  limit, `Vec::with_capacity`, error text "value nesting depth {depth} exceeds
  maximum {max_depth}").
- `Identifier`, `Bytes20/32/36`, `BinaryData` bincode and serde encodings, and
  the `Identifier` `PlatformVersionEncode`/`PlatformVersionedDecode` impls.
- Every `platform-serialization` free function, trait and impl under default
  features, including `MAX_COLLECTION_LEN`.
- `platform_value!` macro output (only the internal `vec!` path changes).
- All public function signatures; gated items keep their signatures under
  default features.

## 10. Risks and how the plan handles them

- Feature unification hiding a std leak: guarded by `wasm32v1-none`, which has
  no std library, so the check cannot pass with a leak regardless of unification.
- Breaking a derived `Decode` in dpp: the blanket `impl<Context>` for `Value`
  stays; `cargo check --workspace --all-targets` proves every consumer.
- Behaviour drift on the native decode path: the extracted state machine is
  the same code; std tests for the thread-local limit and the golden
  guest/native byte-equality tests pin it.
- `cargo machete` false positives on optional deps used only under `cfg`:
  machete greps source, so gated uses count.
- Doctests on gated functions: they compile under default features (the only
  profile that runs doctests in CI).
- wasm32 JS builds (`wasm-drive-verify`, `wasm-sdk`): they consume
  `platform-value` with defaults through `dpp`; `random` keeps `rand` exactly
  as today. Checked locally with the wasm32-unknown-unknown build of
  `wasm-drive-verify`.
